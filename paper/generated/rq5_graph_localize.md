# RQ5 addendum (exploratory): graph-guided localisation (L6) against L1 and L4

Generated by `analysis/localize_eval.py` at git `ac78fc101c79a8f161a7b60ca3694d130ded7699`.

**Exploratory, not pre-registered; produced by `make localize-eval`, not `make tables`.** The pre-registered E3 analysis is unchanged and the E3 arms are not re-run. No LLM is involved.

## Method

L6 ranks every function of the source files by reciprocal rank fusion (k = 60) of four rankings: the function overlaps a changed line; minimum hop distance from a failing test's node over `calls` edges (caller to callee, at most 6 hops); the number of failing tests whose `calls` closure reaches it; the function holds a frame of a failing test's traceback (deepest first). Ties at equal rank share it; the fused order is broken by file path, then line. L1 and L4 are the E3 retrievers (`repair.select_chunks`), with the cut at three chunks lifted to read the rank of the ground truth. The graph is built once per repository at the base commit with `src.graph.build.build_graph_at`.

## Reading

standard: hit@3 is 46/70 (L1), 69/70 (L4) and 69/70 (L6); L6 is equal to L4 on hit@3 and below it on hit@1 (58/70 vs 63/70).

hard: hit@3 is 46/70 (L1), 63/70 (L4) and 36/70 (L6); L6 is below L4 on hit@3 and below it on hit@1 (32/70 vs 49/70).

The graph signals rarely fire: over both variants a failing test is a graph node on 118/140 tasks, but its `calls` closure reaches a source function on only 8/140 (the static graph resolves few calls made through objects), so L6 is mostly the diff and frame signals fused. On the hard variant the diff signal ties the seeded function with the decoy edits, and the fusion does not separate them as L4's BM25 does.
