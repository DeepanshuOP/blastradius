# RQ4 / E3: change-aware repair on BR-Seeded

Generated by `analysis/rq4_repair.py` at git `84a3a30ee0084565b44773412c104a86741f64a3`.

Produced by `make repair-eval` from cached LLM responses under D-58 / D-60. It is NOT part of `make tables`, and its repair numbers depend on the recorded model replies (`eval/llm_cache/`). Detection and retrieval need no model. Analysis plan: `docs/phase/033-e3-preregistration.md`.

BR-Seeded: one mutation operator applied to a function covered by the suite (so at least one test fails), plus 2-3 harmless distractor edits in other files; the diff is the 'PR'. The **hard** variant is the same 70 mutants with 4-6 additional no-op edits (a comment line or redundant parentheses) inside functions the failing tests execute. A patch is accepted only if the FULL suite (minus tests already failing at the base) passes. Seeded bugs are simpler than real ones; this measures what retrieval and change-awareness add, not absolute repair ability.
