| **D-25** | Test identity two-key model | **Adopt a two-key model distinguishing canonical dataset `test_id` from internal `graph_node_id`, mapped deterministically via a one-way lossy derivation function.** (a) `test_id` is the canonical, lossless, case-preserving join key that ships in BR-Bench and appears in the paper (Java: `{package}.{Class}#{method}`; Python: `{path}::{Class}::{func}`, with casefold applied to the path component only). (b) `graph_node_id` is an internal, opaque, lossy key used solely to bind a test to a Graphify graph node. It is derived from `test_id` by applying Graphify's `normalize_id` recipe. One deterministic one-way function maps `test_id -> graph_node_id`; this mapping is many-to-one. **Technical basis and evidence:** Graphify's `ids.normalize_id` applies `NFKC`, then `casefold()`, then `NFKC` again, replaces every non-word character (`[^\w]+`) with an underscore, collapses repeated underscores, and strips leading/trailing underscores; `make_id` joins name parts with underscores. Under this transformation, `com.example.FooTest#testBar` becomes `com_example_footest_testbar`. Furthermore, Java method node IDs carry only the simple method name with no parameter signature (verified: `_JAVA_CONFIG` specifies no `resolve_function_name_fn`, so `_extract_generic` falls back to the tree-sitter `"name"` field). **Why not adopt Graphify's normalized ID as canonical `test_id`:** Casefolding an identifier merges `testBar` with `testbar` and `FooTest` with `Footest`. Java and Python are case-sensitive languages. In a relational join between harvest labels and code entities, an identifier collision does not raise an error — it manifests as a silent false-positive join, which is the worst failure mode available to this benchmark dataset. **Why not force Graphify to preserve case:** Graphify is vendored third-party code (`vendor/graphify-br/`) whose internal extractor, AST indexer, and query routines rely on `ids.py` normalization; mutating vendored third-party code risks breaking the internal consistency of the graphs it builds and diverging from upstream. **Consequences.** (1) D-09's instruction to make our IDs "consistent with graph node IDs" is satisfied by a deterministic derivation function (`graph_node_id = derive_node_id(test_id)`) rather than by literal string equality. A function `derive_node_id(test_id) -> str` must live in `src/parse/test_ids.py` alongside `normalize_test_id()`, applying Graphify's recipe, so there is exactly one implementation of the derivation in this codebase. (2) The many-to-one collision rate MUST be measured and reported as part of the Gate 1.5 binding analysis, not assumed to be negligible. (3) The published BR-Bench dataset carries canonical `test_id`; `graph_node_id` is an ephemeral internal binding key and need not be released. | two-way — changes internal binding derivation without altering canonical dataset schemas or raw harvest captures | Measured collision rate at Gate 1.5 exceeds 1% of bound tests, or any single graph_node_id binds two genuinely distinct test_ids within the same repository — derivation must change |
